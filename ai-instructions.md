# Правила роботи coding agent з репозиторієм FocusStudy

1. **Контекст перед діями:** Перед внесенням будь-яких змін прочитати файли з директорії `docs/` та перевірити фактичну структуру `backend/` і `mobile/`.
2. **План перед кодом:** Спочатку пояснити поточну реалізацію та запропонувати покроковий план із критеріями готовності.
3. **Локальність змін:** Перерахувати конкретні файли для зміни. Не переписувати весь проєкт або непов'язані модулі для локальної задачі.
4. **Захист API-контракту:** Не змінювати існуючі поля запитів/відповідей у `backend/main.py` та `MainActivity.kt` без попереднього узгодження та оновлення `docs/api-contract.md`.
5. **Контроль залежностей:** Не додавати нові бібліотеки в `requirements.txt` або `build.gradle.kts` без чіткого технічного обґрунтування.
6. **Безпека секретів:** Ніколи не записувати `GEMINI_API_KEY`, реальні персональні дані чи вміст `.env` у код, тести, коміти або документацію.
7. **Тестування та підсумок:** Додавати або оновлювати перевірки для нової поведінки, не ламаючи сценарій Лабораторної роботи 2. Після кожного кроку підсумовувати змінені файли та команди перевірки.
