# Вимоги до системи (Requirements)

## Реалізовані функціональні вимоги (Лабораторна робота 2)
- **FR-1:** Введення навчальної теми (від 3 до 120 символів) та часу (від 25 до 300 хвилин) у мобільному клієнті.
- **FR-2:** Валідація введених даних на стороні Android-клієнта до відправки мережевого запиту та на стороні сервера через Pydantic (`422 Unprocessable Entity`).
- **FR-3:** Генерація структурованого навчального плану у форматі JSON із розбивкою на 25-хвилинні інтервали та порадою на перерву.
- **FR-4:** Наявність ендпоінту перевірки стану сервісу `GET /health`.

## Незавершені функції (Backlog)
- Вибір рівня складності / інтенсивності сесії (заплановано до реалізації у Лабораторній роботі 3).
- Локальне або серверне збереження історії згенерованих планів.
- Вбудований Pomodoro-таймер для запуску обраного кроку.

## Критерії готовності (Definition of Done)
- Клієнт та сервер успішно запускаються згідно з `README.md`.
- Запит `POST /api/plan` повертає валідний JSON зі статусом `200 OK` та відображається у вигляді списку карток в Android UI.
- Некоректні вхідні дані коректно обробляються без аварійного завершення застосунку.
