# Архітектурні та технічні рішення (ADR)

- **ADR-001: Використання FastAPI як проміжного бекенду замість прямого виклику Gemini з Android.**
  *Причина:* Захист `GEMINI_API_KEY` від декомпіляції APK-файлу та централізована валідація даних.
- **ADR-002: Застосування `adb reverse tcp:8000 tcp:8000` та `localhost` у Retrofit.**
  *Причина:* Стабільна локальна маршрутизація між емулятором Android та локальним сервером Windows незалежно від налаштувань брандмауера для `10.0.2.2`.
- **ADR-003: Збільшення таймаутів OkHttp до 60 секунд.**
  *Причина:* Генерація структурованої відповіді LLM займає більше часу, ніж стандартні 10 секунд таймауту OkHttp.
- **ADR-004: Реалізація Graceful Fallback у `POST /api/plan`.**
  *Причина:* Забезпечення стабільної роботи застосунку навіть при тимчасовій недоступності (`503`) серверів Google Gemini.

### ADR-004: Декомпозиція FastAPI Backend та виділення інтерфейсу PlanProvider (Лабораторна робота 5)
* **Контекст:** У початковій реалізації (`v1.x`) маршрутизація HTTP, зчитування змінних середовища, бізнес-логіка та прямі виклики Google GenAI SDK були змішані в одному файлі `backend/main.py`, що унеможливлювало модульне тестування без реального API-ключа та доступу до мережі.
* **Рішення:** Обрано Варіант Б (оптимізація архітектури FastAPI). Виділено інтерфейс `PlanProvider` (`typing.Protocol`) із двома реалізаціями (`GeminiPlanProvider` та `MockPlanProvider`), впровадження залежностей організовано через `FastAPI Depends`, а технічні збої провайдера перетворено на контрольовані доменні винятки (`ProviderUnavailableError`, `InvalidPlanCriteriaError`) з централізованими обробниками HTTP-помилок і наскрізним `X-Request-ID`.
* **Наслідки:** Прикладна логіка перевіряється швидкими автотестами (`pytest`) без зовнішньої мережі; зовнішній JSON-контракт `POST /api/plan` залишився без змін, тому Android-клієнт працює без модифікацій.
